# Yomichi design

Approved conversation brief: independent open-source TypeScript Japanese analysis engine, PostgreSQL server storage, HTTP API, CLI, light client SDK and standalone multilingual Playground. No Python/Lisp/Rust production dependency. No multi-GB dictionaries in npm packages. Ichiran/Himotoki are algorithm references; ichi.moe is the functional reference, not source to copy.

This is architectural work. Implement an honest alpha vertical slice first, not a claim of complete Ichiran parity. Core performs dictionary-driven candidate generation, finite morphology rules and bounded Top-K dynamic programming. Repository batch lookup decouples algorithms from PostgreSQL. Unknown text stays visible and has no fabricated reading/gloss. Scores are ranking heuristics, not probabilities. Return UTF-16 offsets into unmodified input, nested components, conjugation steps and word alternatives. Spaces and explicit code-unit boundaries prohibit crossing. Limit input to 500 code points and K to 5.

Stream JMdict and KANJIDIC2 XML (or gzip) offline into PostgreSQL. Preserve entry IDs, readings, restrictions, senses, language and POS entities. Store base entries and generated selected morphology forms, not a claim to implement all original conjugations. Import into a staging dataset, then atomic active-dataset switch; include SHA256/version metadata. Never rebuild data at server startup. Bound batch lookup and request work. Do not guess data licensing: retain upstream notices and link EDRDG terms; downloaded data stays outside source control.

HTTP endpoints: analyze, romanize, reading, word search/detail, kanji detail, health/readiness, OpenAPI. Validate body/query/options, limit request size and rate, return stable errors, configurable exact CORS origins and optional API key. No input text in logs. Public Playground may use a public limited API; never embed private API keys in frontend configuration. Separate Vite static deploy and backend deploy; local proxy for development.

Playground: mobile-first light reading surface, EN/ZH/JA chrome, examples, real API requests, ruby display, selectable candidates, word detail drawer/side panel, developer JSON/cURL panel, lookup and kanji modes, keyboard accessibility, loading/error/empty states. Dictionary-not-loaded is an actionable state, never a fake result. Do not store/share input text automatically.

Acceptance: typecheck/build pass; unit tests for Unicode offsets, Top-K, boundaries, morphology and restricted readings; integration tests run schema/import/repository with real PostgreSQL-compatible SQL engine; API injection tests cover failures; browser smoke tests cover desktop/mobile. Full-dictionary quality/performance must be measured separately; no invented RSS/CPU promises. Upstream parity corpus tools identify differences without declaring them all bugs. README explicitly distinguishes implemented alpha features from remaining original scoring/grammar/counter work.
